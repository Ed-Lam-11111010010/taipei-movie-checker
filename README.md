# Movie Checker — 個人非商業 POC｜台北電影場次查詢

Movie Checker 是個人非商業概念驗證網站，不是影城官方服務，也不處理售票交易。

## 網站分頁與導覽

Movie Checker 現在分成四個**真正獨立的網頁網址**，不再把每一種排序模式放在同一個畫面。頂端四項導覽可隨時切換，手機版也可以使用：

| 分頁 | 路徑 | 主要任務 |
| --- | --- | --- |
| 電影 | `index.html`（首頁） | 依海報與電影片名找電影，進入可分享的 `#movie=<片名>` 詳情頁，查看各影城日期、票價參考及訂票入口 |
| 時刻表 | `showtimes.html` | 依開演時間、日期、版本、電影與影城搜尋場次，保留原有詳盡的時刻表功能 |
| 影城 | `cinemas.html` | 影城清單、地址、官方來源；「本站場次」連到已預選影城的時刻表 |
| 地圖 | `map.html` | 地圖選擇影城、行政區篩選與直接查看該影城場次 |

技術架構將原先單一大型 `index.html` 拆成共用 `app.css`、`app-core.js`、`theater-directory.js`、`movie-pages.js`、`movie-pages.css` 與 `demo-catalog.js`，四個 HTML 只共用介面結構，各自提供清楚的頁面定位；都讀取同一份定期發布的 `catalog.json`，不會出現各頁場次各自過期的問題。

原本 672 筆虛構資料仍只能用於明確標示的介面測試，已移至獨立的 `demo-catalog.js`，不會被混入真實來源快照。CSV 個人匯入放到**時刻表 → 進階測試工具**，保持一般使用者畫面簡潔。

## 台北／新北影城完整性清查（2026-11-04）

以 2026 年 9 月整理的 [台北 25 間影城名單](https://unclewriterfilm.com/cinema/taipei-cinemas/) 及 [新北市政府電影場所資訊](https://www.info.ntpc.gov.tw/%E6%96%B0%E5%8C%97%E5%BD%B1%E8%A6%96%E5%9C%88/%E7%9C%8B%E9%9B%BB%E5%BD%B1/)、[Moovie Time 影城清單](https://www.moovietime.com/cinemas) 比對，網站目前納入 **38 個影城／放映場地**：

- **台北市 25 間**：涵蓋大型連鎖、獨立影城、藝術電影館與景美佳佳二輪戲院。
- **新北市 13 間**：沿用原先 4 間威秀，新增包括三重天台、喜樂時代永和、土城秀泰、府中15、新莊晶冠國賓、新莊鴻金寶麻吉、林口昕境國賓、淡水禮萊國賓與樹林秀泰等 9 處。

**「納入影城名錄」不等於「取得該影城電影場次」。** 原本的 12 間影城維持原有同步。新增 26 間的影城專屬開眼電影網場次頁已加入排程；其中府中15另嘗試新北市官方月曆場次表。**2026-11-04 首輪驗證新增 21 間、共 33 間；第二輪已驗證全部新增 26 間、總共 38 間，產生 2,029 筆場次；後續完整來源頁刷新提升至 2,970 筆場次（含 11/04 的 1,124 筆與 11/05 的 1,709 筆）**，其中府中15採新北市政府官方每月放映表。這是已完成排程的成功快照，不代表每一間在所有日期都有完整場次；若某影城日後無法安全解析，會退回「尚未串接」標示。實際每次成功間數以最新 `catalog.json` 為準。未成功的影城不會被標成「0 場」或填入測試資料；點選來源連結可自行核對。

新增的 26 間候選影城持續保留在 `theater-directory.js`。自動排程依此清單擷取來源；**當次實際解析出有效場次的影城**才會另外加入 `catalog.json`，避免把沒有資料的影城列為已同步。每次 Actions 更新後，網站會依最新已驗證來源重新判斷標籤。這是公開名錄的覆蓋性清查，**不是對營業狀態的即時全面保證**；暫停營業、短期影展、私人放映空間或新開幕影城可能需要再確認與補登。未提供官方網站的場館會改列第三方資訊來源而不假稱官方。

## 依電影瀏覽與官方訂票（Movie-first）

網站首頁優先顯示「上映電影與線上訂票」：以海報為主的電影總覽，可以依 **最多場次／最快開演／電影名稱** 排序及搜尋片名。點進電影後，可按上映日期、影城篩選，查看未開演的日期、時間、版本、一般全票參考價，以及對應的影城官方購票入口。每部電影有可分享的網址 `#movie=<URL 編碼電影名稱>`。原本的場次、影城與地圖清單仍在頁面下方。

**購票連結不是「場次已預選」保證。** 只有來源提供且驗證過的場次專用訂票 URL 才可視為直接場次連結。目前的自動快照主要只有片名、日期及時間，沒有官方 session ID，因此電影詳情與原本場次卡會導向可信任的官方售票頁，使用者必須在官方網站再次選擇相同電影、影城、日期與場次：

- 威秀：`https://www.vscinemas.com.tw/vsTicketing/ticketing/ticket.aspx`（官方線上購票入口；部分威秀場次資料來自開眼電影網備援）
- 國賓：`https://booking.ambassador.com.tw/`（國賓官網連結的訂票入口，可能要求登入）
- 欣欣秀泰：`https://www.showtimes.com.tw/cinemas/2/`（秀泰官方欣欣影城場次頁，進一步點選官方時刻即可購票；非開眼場次頁）

**票價標示是參考，不是即時、保證可售的成交價**。一般數位 2D／3D 全票來自威秀、國賓的公開票價公告；國賓大戲院按影廳顯示全票價格範圍，因來源快照未含完整影廳代碼。欣欣秀泰一般全票 NT$330、ScreenX NT$430 由公開第三方票價整理提供，會在詳情頁清楚標示「第三方票價參考」。特殊影廳或缺乏可核對版本價目者顯示「請至官方查價」，不擅自套用一般 2D 價格。所有參考價不含額外訂票手續費、優惠、特殊放映或可能的加價。最後價格、餘位、購票限制與付款均由影城官方系統決定。本站沒有處理購票、帳號或付款。

電影頁由 `movie-pages.js` 搭配 `movie-pages.css` 提供，資料仍以 GitHub Pages 的 `catalog.json` 最新已發布快照為準，不會向影城即時發出用戶端請求；已排程同步成功後電影清單和日期將一併更新。未經核對的個人匯入或虛構測試資料不會顯示官方訂票按鈕。

## 查看已發布的來源場次快照

GitHub Pages 會在進入網站時讀取同目錄的 `catalog.json`，**預設展示目前已成功取得的真實來源場次快照**，而不是虛構展示場次。頁面會顯示來源狀態、快照時間和各來源的成功／失敗資訊，並可透過「查看場次」開啟原始來源網站。

電影場次同步從原本 12 間影城擴增至額外 26 間候選影城（只有安全解析成功者才會納入當次 `catalog.json`）：

- 威秀影城：9 間影城會先嘗試各自的官方場次頁；若官方站拒絕 GitHub Actions 的自動存取，改用已核對影城身分的開眼電影網影城專頁，並在來源狀態明確標示備援，不會偽稱官網同步成功
- 國賓影城：國賓大戲院、台北長春國賓影城的官方場次頁
- 欣欣秀泰影城：開眼電影網的欣欣秀泰場次頁
- 新增影城：使用開眼電影網各間影城專屬場次頁，核對影城名稱、日期、片名及時刻後才發佈；對無法解析的影城保留「僅名錄」狀態
- 府中15：優先使用新北市政府公布的官方每月放映表，獨立解析活動場次，並明確保留索票／報名等特殊格式標記（不把場次誤認為可線上直接訂票）

**這不是即時訂票服務。** 已取得資料只代表取得當下來源頁的場次；最新放映時間、取消或售完狀態必須以原始網站為準。某來源未成功取得資料，不代表當日無電影放映。來源檢查超過 12 小時，網站會顯示可能過期提示。

最初發布的人工核對快照包含 2026-11-03 至 2026-11-04、3 間影城的 85 個場次。**2026-11-03 的歷史排程曾成功提交 1,626 筆可解析場次，涵蓋當時的 12 間影城**：兩間國賓直接由官方頁取得，其餘十間採開眼電影網場次頁；威秀官方網頁對 GitHub Actions 回傳 HTTP 403，故採明確標記的備援來源。這次開眼資料主要涵蓋 11/04 與 11/05，11/03 部分日期頁沒有提供可解析場次；這不等於影城沒有營業。以最新 `catalog.json` 及各來源狀態為準，往後每次執行的數量可能不同。來源擷取失敗時不會以虛構資料補齊。

截至 2026-11-04，已成功確認所有 38 間影城都能取得至少一筆有效來源場次，並保留 26 間新增影城的原始來源連結；府中15的公開放映表含售票、報名、索票與多片單元，站內應用會將來源的連結標籤還原為一般片名。每次更新都會重新檢查來源，**不保證往後每一間、每一日皆能成功提供資料**。

## 電影海報

場次卡片會使用**與該電影來源連結直接配對**的海報：國賓採其官方電影場次頁的圖片，其他來源採開眼電影網影城場次頁對應電影的圖片。同步程式只接受相符的電影 ID 或來源電影頁及限定的 HTTPS 圖片路徑，不會根據相似片名猜測圖片。

海報會隨來源快照更新，點擊海報可查看來源電影介紹頁。若來源未提供圖片、外站拒絕載入或配對驗證失敗，卡片會保留「暫無海報」替代顯示。圖片本身仍由原始來源主機提供，本儲存庫不存放電影海報檔案。

## 未來日期場次覆蓋（2026-11-09 修復）

過去主要影城只抓今天起 2–3 天，即使來源已公開 11/12 也會被漏掉。現在每次來源同步會查詢 **至少今天起四個日曆日**（例如 11/09–11/12），並從已核對影城身份的開眼專頁日期導覽中，延伸擷取 **最多今天起七日內已公布的日期**。國賓官方日期頁也嘗試查詢七日內的實際放映場次。府中15保留原有官方月曆解析。

這是**抓取上限而不是資料完整承諾**：只有在來源當天可讀取、日期標題及戲院身份匹配、且場次解析合法時，才會發布到 `catalog.json`。Instagram 的公開貼文和開眼／官方訂票資料可能不同步；本網站仍不自動解析 Instagram 圖片或補造未能驗證的時間。新增查詢可能增加來源失敗或跑步時間，需在首次合併後檢查 Actions 的來源狀態與 11/12 實際場次。

## GitHub Actions 更新流程

工作流程：`.github/workflows/sync-showtimes.yml`，解析器：`scripts/sync-showtimes.cjs`。

- 每天台北時間預定約 02:17、08:17、14:17、20:17 排程檢查，也可從 GitHub Actions 手動執行。GitHub Actions 排程屬盡力而為，可能延遲或漏掉執行；已避開整點以減少壅塞風險。
- 網站首次開啟會讀取已發布的 `catalog.json`；保持分頁開啟時，每約 15 分鐘在前景檢查一次，返回長時間未看的分頁也會重新檢查。若資料沒有變化不會重建頁面；背景更新失敗但現有資料仍新鮮時保留既有畫面。手動的「重新載入已發布場次」仍可立即重試。
- 自動同步成功不代表全部影城在所有未來日期有場次。網站不會虛構未取得的資料；請以來源頁確認，並留意「進階來源資訊（唯讀）」中的部分成功與來源錯誤。
- 以唯讀 HTTP 請求讀取來源頁，解析中文片名、日期、版本、時刻及來源網址，依影城和日期產生場次。
- 驗證日期範圍、時間格式、來源主機、唯一鍵及場次數後，才提交 `catalog.json`，由 GitHub Pages 發布。
- 若來源無法讀取或解析，會記錄錯誤狀態；若所有來源都無法產生足夠資料，工作流程會失敗並保留已發布的快照。這時網站會根據快照年齡提示資料可能過期。
- 解析依賴來源網頁結構及 GitHub Actions 的網路連線；網站改版或站方存取限制可能導致來源暫時不可用。請查看 Actions 記錄確認實際成功的影城與場次數，不要僅以 workflow 存在推定同步成功。

## 虛構資料測試模式

點選「查看虛構測試資料」，可切換到 **672 筆虛構測試場次**，測試電影多選、日期、時間排序、影城篩選及地圖。虛構資料在瀏覽器會平移成以台北今天起算的 14 天，**絕非真實電影場次**。點「返回來源場次」可回到目前已發布的快照。

## 在瀏覽器匯入個人 CSV（POC）

可在「個人場次 CSV 匯入」區塊選擇 CSV 檔案，或展開「直接貼上 CSV 文字」貼入資料。欄位為 `cinemaId,title,date,time,format`；日期 `YYYY-MM-DD`、時間 `HH:mm`，採台北時間。影城代碼須為本站追蹤的 12 間之一，單次最多 2,000 筆、256 KB、日期須在未來 180 天內。

**個人匯入的資料只保存在當下瀏覽器記憶體，不會上傳 GitHub、更新公開快照或向影城發送請求。** 重新整理或「恢復已發布場次」即可回到公開快照。匯入內容一律標示「未經驗證」。

## 公開檔案與來源

GitHub Pages 網頁資產包含四個主頁 `index.html`、`showtimes.html`、`cinemas.html`、`map.html`，共用資產 `app.css`、`app-core.js`、`theater-directory.js`、`demo-catalog.js`、`movie-pages.js`、`movie-pages.css`，以及 `catalog.json`、`README.md` 和 `.nojekyll`。自動更新使用 `.github/workflows/sync-showtimes.yml` 與 `scripts/sync-showtimes.cjs`，不包含 API 密鑰或私人同步設定。

來源網站內容可能受到各網站的使用條款與更新政策規範。這個小型個人 POC 只顯示必要的事實性場次欄位及來源連結，不代理售票、不保證資料完整性或使用權；如來源條款不允許持續自動存取，應停用相關解析來源。
